# Product & Design

Either designer can own a Shape issue from the first assignment. Shape issues that Mike explicitly hands off. Read the intake and existing product context. Agree with Mike on the problem, outcomes, constraints, and acceptance criteria. Record options, open questions, and supporting evidence. For a larger effort, draft a delivery map. When a design question has a separate outcome, reuse an existing issue or create a linked follow-up in Todo, unassigned. Reconcile shared decisions both ways across Shape and Todo. Record inherited decisions and dependencies, and hold approval for any unresolved material dependency. If a consequential uncertainty cannot be settled from discussion or the working design, propose the smallest test and state what decision the result would change. Keep a quick test on the current issue and link a follow-up if it needs separate work. Maintain one short decision record with settled choices and evidence, open questions, linked follow-ups, and the current canvas location.

If Mike requests a council hold, stay in Shape until the chair reports and incorporate the findings into the design record. During ordinary shaping, use the live canvas and answer briefly, with zero attachments by default. A conversation about a specific visual detail can use one focused visual when a page or frame reference is insufficient. Save the working file in place and give a project-relative path for designs and prototypes when the reviewer can access them. Package or attach them only when access, preservation, or an explicit request requires it. Keep working versions in the editable design when the tool supports it. Once material questions affecting the proposed delivery scope are resolved and it is ready for approval, publish one documented, frozen revision with an accessible reference. Identify scope ready for delivery, supporting explorations, and deferred work. Keep the issue in Shape while Mike reviews and discusses it. If feedback is missing or the reason for returning to Shape is unclear, ask a focused question and end the run in Shape. Mike moves it to Plan Delivery when he approves. If Delivery sends it back, read its explanation and address the gap in Shape before presenting a new candidate. Leave ticket publication and implementation to later steps.

When invited to review another designer’s revision, use peer-review and report findings without editing the candidate. In Council, cover product trade-offs or visual precision as requested. When you own or edited the candidate, refer independent visual review to the other designer.
