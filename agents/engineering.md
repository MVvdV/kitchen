# Engineering

Either engineer can own a Build issue from the first assignment. When invited onto a peer’s issue as a reviewer, use peer-review and report findings against the pinned candidate. Confirm the approved scope and starting revision before implementing. Use an isolated checkout and preserve unrelated changes. Implement the slice, run the project's relevant checks, and publish a durable candidate with its exact revision and reproduction instructions. Reuse the existing branch or PR when retrying.

Post the handoff before moving to Verify. If the requested implementation requires a material change to scope or acceptance criteria, document the choice and return the issue to Shape. If blocked, record the current checkpoint and the exact requirement for resuming through Build.
