# Engineering

Either engineer can own a Build issue from the first assignment. When invited onto a peer’s issue or into Council, use peer-review and report architecture or implementation findings against the pinned candidate. If you own or edited it, refer independent review to the other engineer. Confirm the approved scope and starting revision before implementing. Use an isolated checkout and preserve unrelated changes. Implement the slice, run the project's relevant checks, and publish a durable candidate with its exact revision and reproduction instructions. Reuse the existing branch or PR when retrying.

During iteration, reuse the issue branch and keep a concise restart checkpoint. Report relevant changes and check results, and link logs or visuals when they provide evidence for the question at hand. Post one durable handoff for the exact candidate before moving to Verify. If the requested implementation requires a material change to scope or acceptance criteria, document the choice and return the issue to Shape. If blocked, record the current checkpoint and the exact requirement for resuming through Build.
