# Prototype Question

Name the question and what outcome would change the design decision. Select the smallest prototype that can answer it. Include realistic inputs or an example interaction where they affect the answer.

Put editable working files in the owning issue's `artifacts/<issue-id>/design/` folder. If a prototype spans several issues, link the owner and exact base revision from each contributor. Keep variants and review evidence under their own issues and let the owner integrate accepted changes.

Return an accessible, revisioned snapshot or runnable bundle, how to exercise it, what it demonstrated, and what remains uncertain. Include the dependency lockfile for a runnable code prototype when available. Pair native design files with a preview that another tool can open. Treat production implementation as a separate decision.
